# Glossary — measurement & search-performance shorthand

Plain-language definitions for the shorthand used in R-LOAD (#779/#782)
status messages, load-test reports, and issue comments. Add to this file
whenever a new label, metric, or id appears in a report.

## Metrics

| Term                                       | Meaning                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **p50 / p95**                              | Percentiles. p50 = the median: half of the measured builds were at least this fast. p95 = 95% were at least this fast — the "slow tail". With only 5 probes, p95 is effectively the slowest completed one.                                                                                                                                               |
| **lead metric**                            | The number R-LOAD is judged on (owner-defined 2026-08-25): the wall-clock a first-time user waits for a **cold, novel** Research search — nothing cached anywhere, a question nobody has asked before. Reported as p50 / p95 over the 5 P0 probes. Budget: **30s p50 / 60s p95**.                                                                        |
| **cold / warm**                            | Cold = every cache emptied first (Redis keys for expansion, validation counts, arms, judge picks, in-flight markers) AND the database's page cache not holding the relevant rows. Warm = caches populated by a previous run of the same question. "Attested cold" = the reset script recorded the key counts it cleared, so the report proves the state. |
| **tResults / t_results**                   | Client-measured seconds until the browser would have a usable document list. Quantized by the client's poll cadence (~16s steps), so small deltas between runs can be one poll boundary.                                                                                                                                                                 |
| **tBuildComplete / t_complete**            | Client-measured seconds until the server confirmed the build was cached. Usually equals tResults; differs when the client gave up first.                                                                                                                                                                                                                 |
| **DNF**                                    | "Did not finish": the probe passed the client budget (**240s**) without a usable result. Counted separately (`dnf240s`) and excluded from p50/p95, which is why a DNF can hide inside a good-looking p50.                                                                                                                                                |
| **202s / cuts / 429**                      | Per probe: number of "still building" poll responses; number of Cloudflare 60s edge timeouts the client re-requested through; number of rate-limit rejections (should be 0 — the runner neutralizes rate limits).                                                                                                                                        |
| **totalMs / expansionMs / retrieveWallMs** | Server-side phase timings recorded per build (`search_timings`). `totalMs` is the precise server build time — use it for deltas, since tResults is poll-quantized. `expansionMs` (validated search terms) precedes `retrieveWallMs`; they add up to roughly `totalMs`.                                                                                   |
| **stage rows**                             | Server-side per-stage timings inside one build (`seed-expansion`, `seed-vector-action`, `seed-alias-arms`, `seed-mining`, `judge`, `arm-fanout`, …). Defined in `scripts/loadtest/README.md` → "Seed stage rows".                                                                                                                                        |
| **DEGRADED**                               | A server log line meaning a build silently lost work: an alias arm or a validation count timed out after retry and was dropped. Acceptance for any perf change requires zero of these during the run.                                                                                                                                                    |

## Runs and labels

Report files live in `scripts/loadtest/reports/<date>-<profile>-<label>.json`.

| Label                 | What it measured                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **P0 / p1 / p2 / p3** | Load-test profiles. **P0** = the lead metric: 5 sequential cold novel Research probes, one user. p1 = browse-only baseline; p2 = browse + one research build; p3 = ramp of concurrent distinct builds. |
| **db-basic4gb**       | Round A baseline on the current prod DB tier (Render basic-4gb, 2 vCPU), 2026-08-26, code v1.16.8.                                                                                                     |
| **c8**                | Same tier after WO-3 (arm/count query concurrency 5→8). The reference point every later run is compared to.                                                                                            |
| **wo2**               | WO-2 arm pruning build (reverted).                                                                                                                                                                     |
| **wo5**               | WO-5 stage-overlap build (`511afef`), knob off.                                                                                                                                                        |
| **wo5-pw8**           | WO-5 build with the per-window DB budget (`DB_CONCURRENCY_PER_WINDOW=8`: 8 concurrent statements per window, 24 for a 3-era question); process-wide knob off.                                          |
| **wo5-d**             | Option D, the final WO-5 shape: expansion first and alone, then alias arms overlapped with vectors → mining under the per-window budget.                                                               |
| **wo5-gate8**         | WO-5 build with `DB_WORK_CONCURRENCY=8` (a process-wide cap on concurrent arm + count statements).                                                                                                     |
| **WO-n**              | "Work order n" under #782: WO-1 batched validation SQL (refuted), WO-2 arm pruning (reverted), WO-3 concurrency 8 (adopted), WO-4 chip-wall UX (not started), WO-5 stage overlap (measuring).          |
| **Round A / Round B** | Round A = full profile suite on the current tier. Round B = the same suite on the next DB tier (8GB), only if justified.                                                                               |

## Golden guard (`pnpm retrieval:golden`)

| Term                    | Meaning                                                                                                                                                                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **capture A1 / A2**     | Two recordings of retrieval shape on the pre-WO-5 code (`e8ee16b`); their diff is the noise floor.                                                                                                                                           |
| **capture B / B2 / B3** | Recordings on the WO-5 code (`511afef`). B was made before a capture bug was fixed (term names recorded empty); B2/B3 are the valid ones.                                                                                                    |
| **candidatesPreRerank** | The document ids (with the search arm that found each) going into the final ranking — the actual retrieval decision. Must be identical across a scheduling-only change.                                                                      |
| **alsoSearched**        | The search-term chips shown to the user (expansion + corpus-mined + salience terms). Compared as a set.                                                                                                                                      |
| **drift vs noise**      | Drift = a retrieval decision changed (fails the gate). Noise = known run-to-run variation on identical code: final document order (uncached LLM reranker), the trace's re-run narrowing proposal, and salience picks on multi-era questions. |

## Retrieval pipeline stages (one Research build)

| Stage                     | Meaning                                                                                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **expansion**             | An LLM proposes search terms for the question; each is validated by counting corpus matches ("validation counts"). Survivors become "aliases".                                                                                  |
| **vectors**               | Semantic (embedding) search, one query per document tier (action / discussion).                                                                                                                                                 |
| **arms**                  | Per-alias keyword searches (full-text) returning ranked document ids. "Alias arms" = from expansion; "mined arms" = from terms mined out of the vector candidates' text; "salience arms" = hot entities picked by an LLM judge. |
| **mining**                | Extract entity phrases from the vector candidates' text, validate them like aliases, run them as arms.                                                                                                                          |
| **fusion / fuse-hydrate** | Merge vector results with arm results (rank fusion), fetch the full rows for winners.                                                                                                                                           |
| **judge / arm-fanout**    | The salience stage: LLM picks hot entities; their arms run; guaranteed slots reserved for their hits.                                                                                                                           |
| **rerank**                | Final LLM pass ordering candidates by bearing on the question (uncached, nondeterministic).                                                                                                                                     |

## Search front door (R-HARDEN-SEARCH, #791–#795)

| Term                       | Meaning                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **pass**                   | The human credential for expensive search paths: a signed, HttpOnly `dm_pass` cookie (6 h) issued by `POST /api/search/pass` after an invisible Cloudflare **Turnstile** check. Cached answers never need one; a request that would start a cold build or a stream does.                                                                                       |
| **machine token**          | `Authorization: Bearer <SEARCH_MACHINE_TOKEN>` — how our own harnesses (prewarm workflow, eval, loadtest, golden guard) pass the front door.                                                                                                                                                                                                                   |
| **source**                 | The identity fairness and spend are accounted against: a pass id, a machine token (per IP), or the client IP when enforcement is off.                                                                                                                                                                                                                          |
| **source slots**           | Concurrent work one source may hold: 2 cold builds (one in flight + one "wrong question"), 1 stream. Exceeded → `429 source_busy`. The global cap of 3 concurrent builds still applies.                                                                                                                                                                        |
| **spend unit**             | What the daily budget counts, at admission: a `build` (uncached research build) or a `stream` (one uncached Sonnet synthesis).                                                                                                                                                                                                                                 |
| **daily budget / breaker** | Per source 30 builds + 60 streams per UTC day → `429 daily_budget` for that source only; global 600 builds + 1,200 streams → `503 search_paused` for new builds and streams while cached answers keep serving. Alerts at 50% and 100% of a global unit and on >60 novel builds in an hour. `SEARCH_SPEND_BUDGET=off` disables rejections (counting continues). |
| **dev lifecycle**          | `pnpm dev:status / dev:suspend / dev:resume` — suspend and resume the dev web service and database through the Render API between gate runs.                                                                                                                                                                                                                   |

## Credibility guards (R-CREDIBILITY, #667 #700 #711 #714 #744 #741 #772)

| Term                        | Meaning                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **reconciliation (scores)** | The snapshot step, before `validate:graph`, that scores and re-aggregates every eligible document still lacking a score row (analysis periods only, ≤30 category-weeks per run; baseline weeks reported, never touched). Fixes the late-published-document class that held the digest (G1a) on three Mondays.                                                                                  |
| **G1a sample**              | The graph check now names up to five offending documents (`#id category origin date`) instead of a count per category.                                                                                                                                                                                                                                                                         |
| **number check**            | Deterministic check on every weekly summary: each count/total claim must be a figure from the FACTUAL DATA block (the **allowed set**: block integers + years + category count), and each enumeration's count word must match the names listed. One targeted revision pass, then the digest is **held** with the figures named.                                                                |
| **enumeration mismatch**    | "Four categories — A, B, C, D, E, F —": count word ≠ list length. Definitive error class (found stored at 2026-07-20 and 2026-07-27).                                                                                                                                                                                                                                                          |
| **`narratives:verify`**     | The repeatable survey of stored summaries against today's data, three classes: enumeration (definitive), category counts (probable), document totals (drift — covered by the as-of stamp).                                                                                                                                                                                                     |
| **empty_synthesis**         | Stream error code after two draws produced no text; the first empty draw is redrawn invisibly inside the request.                                                                                                                                                                                                                                                                              |
| **masthead offset**         | Per-origin skip in `headlineSourceSql` so `ts_headline` never sees a GPO header/CSS preamble/hearing bracket; the fragment filter (`dropBoilerplateFragments`) is the belt. `pnpm verify:enrichment-sql` executes every branch — the only loud check on a failure-tolerant path.                                                                                                               |
| **revision cluster**        | CourtListener's second cluster for a revised slip opinion — same case, category and decision day, different URL. The older row is marked **superseded** (`retrieval_relevant=false`, `counting_scope=false`, `metadata.supersededBy`) and its score/AI-review rows cascade; the document row is never deleted.                                                                                 |
| **cluster ledger**          | `cl_cluster_ledger`: every attempted CL opinion cluster with its outcome (`stored`, `no_text`, `zero_categories`, `fetch_error`) and attempt count. `no_text`/`fetch_error` retried up to 6× by the 42-day **trailing pass** (≤100 fetches/run).                                                                                                                                               |
| **Relating-to**             | CourtListener's precedential status for emergency-docket ("shadow docket") orders; excluded by the search default, now requested (`stat_Relating-to=on`).                                                                                                                                                                                                                                      |
| **era rates**               | `/api/methodology/verdict-rates`: Pass-1 flag rate, Pass-2 departure rate, clear-departure rate and audit-sample miss rate for every analysis period, side by side on the methodology page.                                                                                                                                                                                                    |
| **mirror arm**              | The swap audit run the other way (`--from 2021-01-20 --to 2023-01-20`): Biden-era documents renamed to the current administration. Distinguishes a partisan prior (verdicts move up) from incoherence discounting (verdicts move down either way).                                                                                                                                             |
| **swap audit**              | `pnpm audit:symmetry`: per reviewed document, a **control re-run** (unchanged text — the model's own noise) and a re-run with administration-identifying tokens exchanged; the **flip rate** is the share of pairs whose verdict crosses the concerning line, reported net of the control's disagreement with a **Wilson 95%** interval.                                                       |
| **trailing window**         | An ingest step that re-queries a long window each run (CPD 120 days, CourtListener opinions 42 days, CHRG 540 days) and skips packages already stored, so a source whose publisher loads documents late (GovInfo's **load lag** for CPD is ~7 weeks after the issue date) is still picked up. The alternative — asking only for last week — logged "no new documents" for seven months (#798). |

## Pool hygiene (R-POOL-HYGIENE, #799–#805)

| Term                       | Meaning                                                                                                                                                                                                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **pool**                   | The documents handed to synthesis for one research question (60 on the enumeration path, 30 analytical). Its served order is the citation order — `[Doc N]` in the answer is position N.                                                                                                                      |
| **seed sweep**             | The vector + fusion retrieval that fills the first half of an enumeration pool. Docs carry `provenance: 'seed'`.                                                                                                                                                                                              |
| **arm pool / arm slots**   | The other half: up to 30 guaranteed slots (2 per arm, 18 arms) filled by alias-arm FTS hits — expansion, mined and salience aliases alike (R-SLOTS). Docs carry `provenance: 'arm'`. Before #800 they were hydrated without the query vector (cosine 0) and interleaved one-for-one with seed docs, unranked. |
| **mechanical top-up**      | Up to 8 salience arms that run regardless of the judge's picks, ranked by corpus breadth (#762). Since #799 it never draws from the **global channel**.                                                                                                                                                       |
| **global channel**         | The salience nomination channel that lists an era's top-breadth entities regardless of the question (`queryGlobalTop`). Question-blind by construction; its entities reach the judge but not the top-up.                                                                                                      |
| **arm share (top-10)**     | Hygiene metric: fraction of the first ten citations that entered through an arm slot. Baseline 2026-08-29: 30% novel / 40% outreach; gate ≤ 15%.                                                                                                                                                              |
| **shared aliases**         | Hygiene metric: aliases searched on ≥ 4 questions of a run. Baseline 67 ("Public Law 119-21" on 29 of 31 questions); gate ≤ 10.                                                                                                                                                                               |
| **recurring docs**         | Hygiene metric: documents present in ≥ 3 different pools of a run. Baseline 84; gate ≤ 25.                                                                                                                                                                                                                    |
| **hygiene bank / battery** | `scripts/hygiene-questions.json`: 12 **novel** questions (written 2026-08-29, never tuned on, a third rotates out per retrieval sprint) + the 19 outreach questions (tuned on, reported not held out). `pnpm retrieval:hygiene` captures them docsOnly ($0 synthesis) and gates on the metrics above.         |
| **`ENUM_POOL_RERANK`**     | Env knob (#800): the tier-balanced reranker now runs over the composed enumeration pool (default on); `off` serves the cosine-ordered seed/arm interleave.                                                                                                                                                    |
| **build stamp**            | `builtAt` / `builtBy` on every docsOnly payload (v1.18.2): when the pool was built and by which commit. The hygiene `--refresh` capture polls plainly after an edge cut and accepts only a stamp newer than its request — a plain poll during an in-flight rebuild is otherwise served the week-old cache.    |
