## Sprint R-SEARCH-ORTHOGONAL: the corpus and search are independent of the analysis (#887–#897, milestone 141; Phase 3 in milestone 142) — 🟡 built 2026-09-15; release + runbook #897 pending

**Origin**: the owner's 2026-09-08 review of the R-INFOAVAIL annotation ("are these documents not worth storing?") answered itself — within what a sanctioned fetcher returns, nothing is worth excluding on topic grounds — and the July #544 rule ("must not reach assessment, statistics, search, or exports") had hidden ~57k stored Federal Register documents from search. On 2026-09-14 the owner added two requirements: recover documents that snapshots filtered out BEFORE storing them, and keep pulling search-useful documents into the database going forward even when they are not analysis evidence.

**Diagnostic (prod, read-only, 2026-09-15)**: 439,403 rows / 306,846 URLs; off-topic rows 88,232 (FR 87,616, CL 611); 57,328 FR URLs with no searchable row (11,106 in the current term); fetch-time ledger 325 rows since 2026-07-13, 208 URLs never stored. A fetch-time gate inventory found the same discard pattern, unrecorded, in CHRG (`chrg_seen_ledger` 903 zero-category transcripts, text thrown away), CL opinion-first (15), CREC (`routeItemsToCategories` drops with no record — the largest loss), CPD (unmapped subjects skipped before content; 34 of 49 in one run), DOJ (component mismatch, ~48% of the feed), LegiScan, DHS local releases, RECAP party papers. Sizes: database 22.65 GB of 30 GB (documents 21.6 GB: TOAST 18.1, HNSW 1.60, GIN 1.06), plan 2c-8g, ~110 MB/week growth, dump 8.07 GB/18.6 min. Bytes per row incl. indexes: FR 32 KB, CHRG 155 KB, CL 50 KB, CPD 40 KB, DOJ 20 KB, CREC 45 KB, LegiScan 16 KB. Dev-copy timings: capped alias counts/arms and the vector query unchanged without the topic predicate; the "Schedule F" count (a 45–60 s cron line) 47.9 s → 0.57 s. Samples of the dropped populations: CHRG = real hearings on other topics; FR drops = exchange rule filings, ICR notices, airworthiness directives; CPD = ceremonial messages and FR-duplicated orders; DOJ = Tax/ENRD/Civil case releases plus AG/DAG/OPA statements; LegiScan = title+description stubs.

**Owner decisions (2026-09-14/15)**: Phase 1 forward = FR, CHRG, CREC, CL, CPD, DOJ (allowlist: AG/DAG/OPA statements + covered divisions; routine Tax/ENRD/Civil case releases skipped). Phase 2 recovery this sprint = ledgered (FR, CHRG, CL) + CPD historical + DOJ allowlisted + CREC current term (~2.7 GB, ~$6 embeddings); CREC 2017–2024 (4.5 GB) and LegiScan deferred to milestone 142. Disk: Render Storage Autoscaling is enabled on the instance (checked 2026-09-15), so no manual resize; the runbook watches the storage percentage between restore steps. Unrouted documents live under pseudo-category `corpus` with both analysis flags false, labelled "Not routed to a category"; Explore defaults to routed documents with a toggle; Research ranks over everything. Assumptions stated with the plan: one approval per restore script run for baseline-era corpus rows (nc:margins before/after), gate thresholds unchanged.

**Built (78 files, +3,381/−251)**: three populations in `lib/db/document-filters.ts` — `searchable()` (body present, not superseded) for search/research/hero/embedder, `countingEligible()` and `retrievalRelevantOnly()` unchanged for analysis; `categoryFacetD` (routed = category + evidence; corpus facet = every unrouted row), `routedOnlyD` (Explore default), `CORPUS_CATEGORY` in client-safe `lib/data/document-populations.ts`. Migration 0071 `documents.superseded` with an in-migration backfill from `metadata.supersededBy` (no window where superseded rows are searchable); the dedupe marker sets it; `cl:dedupe-revisions --backfill-flag` reports 0. Dump/restore carry the column and `init.ts` restores from the CSV header. Search surfaces, similar-docs, research counter, hero (~300k) and embedder switched; keys bumped. Ingest: `SourceFetchResult.excludedItems` channel, `storeExcludedDocuments` (insert-only, never demotes), FR drops stored under the signal category; CHRG/CREC/CL/CPD/DOJ(allowlist) unrouted items stored under `corpus`; the CREC fragment builder skips corpus granules. Invariants: G6 per-table allowlist, live G8 (superseded ⇒ non-evidence and marked; corpus ⇒ both flags false), population-predicates tripwire (search files vs analysis files; the `'corpus'` literal confined), purge guards. `pnpm corpus:restore --source fr|chrg|cl|cpd|doj|crec` (dry-run default, `--max-docs` exit 3, three precheck numbers). `embeddings:backfill --dry-run/--max-docs`, corpus rows included. UI: "Not routed to a category" badge, Explore toggle (`unrouted=1`), research corpus stats labelled. Public wording on the methodology page and ASSESSMENT_METHODOLOGY, ledger policy entry, glossary populations table, data dictionary, PROJECT_KNOWLEDGE constraint.

**Design calls (technical)**: hybrid home for unrouted rows (signal category for single-signal sources, `corpus` for cross-cutting ones) so the FR ledger contract and the 57k annotated rows keep their `(url, category)` shape; the marker keeps setting `retrieval_relevant=false` so G1b/G5 stay the enforcement; `sql.raw` is blocked by the repo's OpenGrep rule, so every predicate is a parameterized template over the `d` alias; the research prompt labels `corpus` for the synthesis model; `fetchDojHistorical` became `fetchDojHistoricalPartitioned` (the only caller needed both halves).

**Dev rehearsal (2026-09-15, stale dev copy)**: migration applied; `--backfill-flag --dry-run` = 0; `corpus:restore chrg/fr --dry-run --max-docs 3` print the prechecks and exit 3 on the cap; `embeddings:backfill --all-dates --dry-run` = 2,185 docs (~5.8M tokens); `validate:graph` G6 ✓ G8 ✓ (the jsonb `?` operator inside a sql template runs); the dev copy's other violations are its own staleness.

**Post-sprint review** (`/code-review high`, 14 verified findings, 0 refuted; lint/patterns/Knip clean, 3,688 tests): every finding applied except per-row inserts in the excluded-document store (fine at ~1k rows). Correctness: the Explore alias-arm cache key now carries the unrouted toggle; research rows carry `retrieval_relevant` and the API payload carries `routed` (an off-topic FR notice no longer wears a category badge in Research or the synthesis prompt); DOJ allowlisted releases travel a separate `corpusItems` channel stored under `corpus` with a URL anti-join across every category (they had been stored once per DOJ signal under the signal's category); the document upsert clears `retrieval_relevant` when a signal returns a formerly dropped document as relevant (superseded rows stay out), so a promoted document cannot be scored while flagged; revision dedupe selects same-day siblings on `superseded IS NOT TRUE` instead of the evidence flag (it had been a no-op for corpus opinions); research corpus statistics bucket unrouted rows as `corpus`; the restore tool stores only candidates with a body (a failed text fetch had produced a searchable-but-empty row that was never retried); similar-documents' cross-category bucket is routed rows in other categories and never the document's own sibling row; `embeddings:backfill` accepts `--category corpus` and exits 3 only when embeddable work remains; the synthesized-answer cache key was bumped with its siblings. Cleanups: the CREC day fetcher takes an exclude set so the restore skips already-stored granules before the per-granule calls (~30–60k avoidable calls over the current term); the DOJ restore reuses the fetcher's exported page walker; `corpus:restore` requires `--baselines` for a confirmed ranged run before 2025-01-20 (the GAO backfill precedent; one owner approval per run).

**Lessons**: (1) "Store everything sanctioned, annotate for analysis" needs a per-population predicate file AND a source-text tripwire, or the next filter will leak into search again the way #544 did. (2) A fetch-time filter that discards is a silent data-loss path: the FR ledger made 208 documents recoverable; CREC's unrecorded drops are unrecoverable except by re-enumeration. Every drop needs an identity record. (3) Size the data before deciding scope: the 4.5 GB CREC history question was a disk decision, not a spend decision, and the dev-copy timings settled the latency worry in an hour.

## Sprint R-LATE-ARRIVAL: late-arriving documents re-derive their true week (#825, #879–#884, milestone 140) — ✅ built + runbook complete 2026-09-14 (v1.31.0–v1.31.3)

**Origin**: three Mondays running (08-31, 09-07, 09-14) the snapshot held the digest on G2b and the owner ran `pipeline:repair` by hand; the week repaired on 09-07 (executiveOversight 2026-08-03) broke again on 09-14. The 09-14 log review traced both mismatches to two net-new GAO reports the Internet Archive captured late (released 2025-02-24 and 2026-08-07), dated by true release date as R-GAO designed ("late arrival, disclosed").

**Diagnostic (prod, read-only)**: `snapshotCategory` stored and scored every fetched item at its `published_at` week, then called `runLayersAndAggregate(items, cat, getLastCompletedWeek())` **once** — L2 and the aggregate pinned to the run week. Two consequences: the old week's aggregate count went stale (G2b), and — worse, invisible until now — the late item's `ai_document_assessments.week_of` was stamped with the run week, so its verdict fed the **current** week's convergence status and never reached its own week, even after a repair (`buildAISummaryFromDB` filters on `week_of`). Population since 2026-06-01 (current-term documents): **~296 Monday-anchored late-stamped rows** — federal_register 148 (P2 audit samples re-drawn on re-fetched Thu/Fri items), govinfo 75, oig 40, courtlistener 22, gao 10, doj 1 — i.e. every category-loop source every week, not a GAO quirk. A second population of **2,423 rows with a non-Monday `week_of`** (courtlistener 2,306, legiscan 105) is a different stamping path → #885. Also confirmed: audit samples come from the same batch (`selectAuditSample`), and L2 dedup is by `(url, category, pass)`, so per-week calls never re-spend and re-running can never fix a mis-stamped row.

**Owner decisions 2026-09-14**: baseline-week G2b mismatches become **report-only** (`G2b-baseline`, warn — the cron may never write those aggregates, so a hold could only be cleared by hand); current-term old weeks get **full in-run re-derivation** (L2 + enrichment, as CPD/CHRG already did) with status flips named for the reversals ledger; the existing mis-stamped rows are repaired in this sprint via a gated runbook (#884). Assumptions accepted with the plan: baseline-dated late items are still stored + scored but get no L2/aggregate in-run (named report with the exact `--confirm-baseline` command); the CHRG snapshot path adopts the same term partition; G7 ships as warn and is promoted to error after the restamp.

**Built**: `lib/services/category-week-grouping.ts` (#879) — one pure grouping (`groupItemsByCategoryWeek`: Monday of `pubDate`, undated → anchor, **in-progress-week items deferred** to their own sweep rather than deriving a partial week; `partitionGroupsByTerm`, `splitGroupsByCategory`, `orderKeysAnchorLast`, `lateArrivalFlips`) replacing the CPD and CHRG hand-rolled copies. `runLayersForGroups` in snapshot-layers.ts (#880): current-term groups re-derive per week (anchor last), baseline groups reported via `describeBaselinePairs`, `captureStatuses`/`diffStatuses` around the old-week re-derivation → `late-arrival status flip(s) in <cat>: <week>: A → B — add a reversals-ledger entry` on the error channel (not a gate input). The category loop, CPD, and CHRG snapshot paths all go through it. Aggregate-parity safety net (#881): `findCountParityMismatches` exported from validate-graph.ts (one G2b definition), `lib/cron/aggregate-reconciliation.ts` bare-recomputes current-term mismatches (enrichment preserved — verified on dev: status and `enriched_at` unchanged, count 59 → 60) right after score reconciliation and before the graph check; deferred/baseline pairs on the error channel with `agg=/scores=` and the repair command. `repairCommandFor`/`describeBaselinePairs` (#882; `describeUnreconciled` now points at `pipeline:repair --confirm-baseline` too). Invariants (#883): `G2b` = current term (error), `G2b-baseline` (warn, live tier), `G7` assessment week = document week (warn), `G7n` non-Monday `week_of` (warn), both naming counts by source. The CHRG backfill CLI keeps its bare aggregates via `aggregateTouchedWeeks` (owner-run, explicit window).

**Design calls (technical)**: the safety net recomputes counts only — a status can move only through the source-side full re-derivation, where it is detected and named (CPD/CHRG re-derived old weeks before too, but unreported). `snapshotChrgWindow` now takes the run's `errors` channel (it swallowed everything before). The G7 SQL anchors on `(published_at AT TIME ZONE 'UTC')` to match `getWeekOfDate`.

**Post-sprint review** (lint / patterns / Knip clean, 3,555 tests): two findings fixed before commit — CPD still called `runLayersAndAggregate` per group directly (no flip reporting for its 120-day window; now through `runLayersForGroups`), and CHRG pushed duplicate "aggregate failed" lines already emitted by the layer runner. Dev rehearsal: `pnpm validate:graph` exercised every new query (G7n on the stale dev snapshot: 15,671, courtlistener-dominated); `reconcileAggregateCounts` on dev recomputed executiveOversight 2025-05-12 and reported 2024-12-09 by name.

**Digest 2026-09-07 (same day)**: released after the two hand repairs; the owner asked for an accuracy read first. Numbers verified (179/515, 3 zero-doc categories, the CISA 214→52 personnel figure, the USDA non-response); one comparative claim false — "largest single-week contraction in the monitoring period" (Christmas week 2025-12-22 matched it on categories and exceeded it on volume; both holiday-recess weeks). One regeneration repeated it (the writer sees two weeks), so one sentence of the expert version was edited by hand and ledgered (v1.31.1); follow-up #886 gives the writer the term series. Also noted: one of the two cited GAO reports (published 09-02) belongs to the prior week — the mis-weeking defect in the wild; status unaffected.

**Runbook (#884, owner-run, no AI spend)**: (1) list the ~296 rows by source and (week_of → true week) + affected category-weeks, dry-run the status diff, post expected flips; (2) `UPDATE ai_document_assessments SET week_of = <true week>` for the current-term set; (3) `pnpm pipeline:repair --from <min true week> --to <run-week Sunday> --expect-flips <file>`; (4) regenerate the current week's narratives if its status/counts changed; (5) reversals-ledger entry; promote G7 to error; (6) baseline rows under `--confirm-baseline`, approval per invocation.

**Runbook #884 executed 2026-09-14 (same day, owner-run through Claude)**: 401 rows restamped (187 true category-weeks, 2025-02-24 … 2026-08-31; G7 → 0), then `pipeline:repair --from 2025-02-24 --to 2026-09-13` — 1,134 aggregates recomputed, NC 6/6, graph ✓, **5 flips**, each a verdict landing in its own week (elections 03-16 and 03-30 → ConfirmedConcern via the fraud-task-force and citizenship-verification EOs, elections 04-20 → Elevated having lost both; executiveOversight 08-03 → ConfirmedConcern via the FEMA workforce GAO; fiscal 08-24 → Elevated via a TIGTA compliance report). Owner accepted all five; ledger `flip` entry; the five category narratives + weekly summaries regenerated; G7 promoted to error (v1.31.2). No baseline rows were in the population.

**Lessons**: (1) A "late arrival, disclosed" design at the fetcher is only half a design — every downstream derivation keyed on the run week (L2 stamping, aggregate, prior-week context, P2 peers) needed the same week-awareness; the fix belongs where the items are grouped, not in one more repair. (2) A count-only invariant (G2b) caught the aggregate but not the verdict mis-attribution — the graph needs an invariant per edge that carries a week, hence G7. (3) The diagnosis found the real population by querying the second consequence, not the one in the issue title (#825 said "baseline-period"; two of three were current-term, and the verdict problem was 30× larger than the count problem).

## Sprint R-TIPWIRE-4: beat tips for feedless reporters, and "did the outlet already run this?" (#872–#878, milestone 139) — 🟡 built 2026-09-08, v1.30.1; gate #878 pending on prod

**Origin**: the owner asked whether the eight roster reporters with no sanctioned byline source (Parloff, Schwellenbach, Natanson, Diamond, Hesson, Aleaziz, Ainsley, Cooke) could get beat tips. The beat pass never needed a feed — its documents are our own Pass 2 verdicts — only `activeReporters()` (active && feed) kept them out. What a feed did supply was the "already wrote it" dedupe, and the owner reframed that: GDELT cannot list articles by byline (no author field), but "did the **outlet** already run this?" is the better question anyway — a colleague's story kills a tip as surely as the reporter's own. The coverage check already asked GDELT about every tip and threw the own-outlet hits away.

**Diagnostic (prod, read-only)**: concerning Pass 2 docs in the last 14 days: immigrationEnforcement 9, civilLiberties 6, fiscal 5, judicialIndependence 3, civilService 2, infoAvailability 2, executiveOversight 2, lawEnforcement 2, executiveActions 1. Five reporters share immigrationEnforcement, so per-reporter beat checks would have produced five near-identical candidates for one opinion. The first live beat block (candidates 14–16, week 2026-08-31) had every coverage line `not-checkable` from 10 s timeouts; GDELT answered the same query in 25 s from the laptop and 429'd a second call minutes later — server-side load, not an IP block — so v1.29.1 raised the abort to 45 s (#867 stays open until a scheduled poll reads `ok`).

**Owner decisions 2026-09-08**: all eight join through ONE owner-scored beat dry run (gate: precision ≥ 0.5 on ≥ 3, zero wrong_fact); one candidate per document with every eligible reporter listed and the owner choosing recipients; the own-outlet signal for every reporter, feed-bearing included; a tip whose check could not run still ships, flagged "search the outlet before sending".

**Built (S1–S6)**: `feedReporters()` (probe/discover/watches) vs `beatReporters()` (active, feed optional) + `--reporter a,b` so the gate reaches inactive entries (#872). Migration 0070: `tip_candidates.beat_category`, `reporter_ids` (snapshot; `reporter_id` = first listed, so the 0069 CHECK is untouched), one index — additive, pinned by test (#873). Coverage keeps every hit and records `hitsByDomain`; `coverage-line.ts` renders `Own outlet — X (domain): N hit(s)` per listed outlet plus `Others: N`, says `unknown … re-run pnpm tips:coverage --candidate N` for checks stored before the split, and `outlet check unavailable — search the outlet before sending` when GDELT was down; no extra GDELT calls (#874). **Beat checks are per category, not per reporter**: `beat-docs.ts` queues one item per category any beat reporter covers, with a per-category clock (legacy per-reporter rows stand in via their reporters — no data backfill) and a global cited-doc exclusion across kinds (#875). `pipeline-frame.ts` builds a multi-reporter frame (titles loaded per reporter; beat anchors never reactive); the prompt gains `REPORTERS ON THIS BEAT`, per-reporter headline blocks with `(no feed — recent headlines unknown)`, and the role sentence "absence of headlines is NOT evidence the story is unwritten"; `TIP_PROMPT_VERSION = tip-2026-09-08-beat-group`; forward and contradiction prompts are pinned byte-identical to a fixture frozen before the edit (#876). Digest blocks list every reporter with cadence + send state; `tips:sent --candidate N --reporter a[,b]` logs one row per reporter and the candidate stays `open` until every listed reporter has one (`--dismiss` closes the rest); a beat check is cadence-skipped only when every listed reporter is held; `scripts/tipwire-beat.ts` + `tipwire-shared.ts` split the 647-line CLI (#877).

**Design calls (technical)**: grouping by category IS the dedupe (each document has one category), so no second mechanism; steady state ≤ 9 beat judge calls per new Pass 2 week (one per category with a beat reporter) vs 3 before. Global exclusion means a document tipped forward to one reporter is never beat-proposed to another — flagged on #875, reversible by scoping to beat rows. The beat frame changed for the three feed reporters too, so the #878 gate covers all eleven.

**Post-sprint review (`/code-review high`, ten verifiers)** — every confirmed finding fixed before commit: the anchor article's own URL is now excluded from its tip's coverage hits (it was flipping forward tips to `likely-covered` once outlet-wide drops went away; `CoverageChecker(keys, excludeUrls)`); the legacy per-reporter clock fallback in `lastBeatWeek` was deleted (a roster edit could silently move it; the three pre-0070 rows re-check once minus their cited docs) and the date cast is UTC-pinned; held reporters are now dropped from a beat candidate's listing and reported as skipped (a stored candidate never lists someone the owner must not send to) and `recordSent` re-applies the cooldown at send time unless `--ignore-cadence`; `--dismiss` with `--reporter` is refused instead of silently dismissing everyone; `recordReply` validates against the listing and the unreplied set with distinct messages; the reminder no longer offers `--dismiss` on a sent candidate (cooldown lifts by itself after 3 weeks); `tips:coverage` also picks up checks stored before the split and never overwrites a measured label with a fresh not-checkable; `tips:score` attributes a category check to every listed reporter; the digest cross-references a reporter listed on several open candidates (`· also on #N`); article rows no longer name the 0070 columns, so a cron on a pre-migration schema still persists them; outlets shared by several listed reporters render once; feedless reporters skip the stored-title lookup; `categoryLabel()` replaces three `categoryLabels([k])[0]` spellings; `listBeatWeeks` uses `getMonday`/`addDays`. Accepted as designed and documented: the cited-doc exclusion is global across kinds AND dismissed rows (one candidate per document, ever; reversible by scoping to beat rows); a multi-category reporter can be listed on two checks in one week (the cross-reference is the guard).

**Lessons**: (1) When only one prompt mode should change, freeze the others into a fixture BEFORE touching prompt code; the equality test is the re-gate exemption. (2) "Drop the reporter's own outlet" hid exactly the signal the owner wanted — a hit is a hit; render the split, do not filter it. (3) `gh issue create --milestone` takes the milestone TITLE, not its number; seven issues silently failed to attach on the first try. (4) A 10 s abort against a service that answers in 25 s reads as an outage; measure latency before suspecting a block. (5) v1.30.0's tag deploy was refused by CI: the prompt fixture had been rendered in the laptop's zone and `formatDate` is zone-sensitive for date-only `publishedAt` (Sep 4 locally, Sep 5 in UTC) — render fixtures in UTC and pin `process.env.TZ` in the comparing test (v1.30.1).

**Next (S7, #878)**: tag release (migration runs in buildCommand, additive) → owner runs `pnpm tips:dryrun --beat --weeks 3 --out DIR --reporter katz,wagner,rosenberg,parloff,schwellenbach,natanson,diamond,hesson,aleaziz,ainsley,cooke --max-calls 30 --confirm` on prod (precheck on dev: see the issue; ≤ 27 checks, ≈ $0.70) → `tips:score` → on PASS flip `active: true` on the eight + release.

## Sprint R-TIPWIRE-2: from retrospective annotation to standing watches — the forward window, the contradiction pass, and the gate that passed (#862–#864, milestone 137) — ✅ built 2026-09-07, gate PASS (3/3 would_send, 0 wrong_fact)

**Origin**: the R-TIPWIRE dry run proposed ten tips on twelve articles and the owner rejected two of the three scored as _already known to the reporter_ — one was literally in the article body. The owner's reframing: an article is a thread the reporter is on; the useful question is _what appeared in the record since the piece was filed_. Approved as "pivot now".

**Planned vs built**: all three issues landed on develop in one commit (7b1b8c0). (1) **Window and watches** (#862): every dated article becomes a 21-day standing watch (`tip_articles.watch_until`, `last_checked_at`); `RetrievalScope` is `forward` (from max(article date, last check) to tomorrow, already-cited documents excluded) or `contradiction` (84 days ending at the article date); an empty forward window is reported as `skippedNoDocs` and costs no judge call; the daily poll runs a contradiction pass over brand-new reactive articles, then a forward pass over every open watch. (2) **Prompt** (#863): `tip-2026-09-08-forward` — the forward role asks what moved on the thread and frames the tip as "since your piece on X, this appeared"; the contradiction role sees the article body (fetched at judge time, bounded to 3,000 chars, never stored) and must cite a predating document that _contradicts_ it — additions are not contradictions; confidence rubric (high = verbatim passage, medium = content excerpt, low = inferred) and `search_keys` for the operator's own check. (3) **Forward dry run as the gate** (#864): same 12 articles since 2026-08-24, forward from each article date. Deviation from plan: none in scope; one in mechanics — the first run against the **dev** database made zero judge calls because the dev snapshot ends 2026-08-24, so the gate run read the **prod** corpus (owner-run; read-only; the dry run writes no tip rows).

**Gate result**: 12 judged, 12 calls (~$0.30), 3 proposed (75% no_tip), owner verdicts 3 would_send / 0 would_not / 0 wrong_fact → precision 100% on 3 decided, **PASS**. The three: the MSPB final rule dropping mandatory Douglas-factor review, published the same day as Wagner's Oyer/MSPB piece; DOJ's Massachusetts-primary monitor release with the cumulative 80-monitor figure, same day as Katz's Dhillon piece; the Federal Register text of the EEOC proposed rule the day after Wagner's vote story (owner: "confirms the flag raised by the article — useful until reporters tell me otherwise"). 25% of articles published before 10:00 ET → the single 21:30 UTC cron slot stands.

**Key decisions**: watches expire at 21 days (three weeks matches the cadence cooldown); cited documents are excluded from later checks of the same watch so a tip is proposed once; the contradiction pass is reactive-only (< 24 h) because a contradiction is only worth a same-day note; the article body is fetched for the contradiction judge and discarded — the no-news-in-`documents` boundary test still passes; a cap trip mid-forward-pass leaves `last_checked_at` untouched for unreached watches so the next run resumes where it stopped. Known gap, accepted at review: an article with no publish date gets no watch and no contradiction pass (it cannot be placed in a window); all twelve dry-run articles carried dates.

**Lessons learned**: (1) Ask the judge the reporter's question, not the archivist's — "what's relevant" produced ten tips of which most restated context; "what happened since" produced three, all accepted. (2) A dry run against a stale snapshot can pass every gate and mean nothing: check `max(published_at)` against the window before spending. (3) Extract the mode-dependent bits (window, structural anchor, body) into a scope object rather than branching inside the pipeline — the poll composes two passes from the same `runPipeline`.

## Sprint R-TIPWIRE: tip candidates for journalist follow-ups — an operator tool built to be killed cheaply (#853–#859 + #860, milestone 136) — 🟡 built 2026-09-07; retrospective gate superseded by R-TIPWIRE-2's forward gate (PASS)

**Origin**: first-round journalist outreach produced acknowledgments and no engagement. The pivot is findings-first follow-ups: a three-sentence tip naming one document, number, or discrepancy relevant to something a listed reporter published this week. The input the project deliberately lacks is what each reporter published; this side pipeline supplies it and drafts candidates. The owner sends manually; nothing auto-sends; no public surface; news never enters `documents`.

**Planned vs built**: all six slices landed on develop (roster + tables + dump exclusion + robots + PK note; acquisition; matching; judge; dry-run packet + score; poll/digest/sent + cron). Two plan deviations, both owner-decided during implementation: (1) **no Google News RSS** — its robots.txt disallows `/rss/search`, and "it's a syndication feed" is exactly the rationalization the probe-gated rule exists to prevent; the pre-existing intent-data use of that endpoint is a discovered discrepancy, filed separately as #860 rather than inherited. Parloff/Lawfare therefore has `feed: null` (manual tips) and **Mica Rosenberg / ProPublica** joined v1 in his place — a better gate subject, since her articles arrive with ledes. (2) **Rosenberg via her ProPublica people page**, not the site-wide RSS: the feed shows only the latest 20 items site-wide, the people page lists 16 of her articles, and article pages carry `parsely-author` metas. NOTUS gained a sitemap intersection (author page ∩ monthly sitemap = dated real articles, newest first) after the first live run wasted its page budget on columnist index links that share the article URL shape.

**Key decisions**: tables over JSONL (a Render cron has no persistent disk); one CLI file with subcommands so the whole tool is one deletion; the category prior is rank-based (+0.15 ≈ 1.5 places in ten) because reranked docs carry no comparable score — the first version silently re-sorted by zeros and discarded the reranker's order; `assertAiCallBudget()` outside the per-article catch, `recordAiCall()` before every request, hard 30-call daily cap with exit 3; the same-story guard reads stored titles in the poll and batch titles in the dry run; the ship gate is precision ≥ 0.5 on ≥ 3 decided tips with zero `wrong_fact`, and fewer than 3 proposed tips is unmeasurable, not failed.

**Evidence**: probes 2026-09-07 (GovExec RSS + `sailthru.author`; NOTUS author page + JSON-LD, Crawl-delay 10; ProPublica people page + `parsely-author`; Lawfare/POGO Cloudflare-walled; news.google.com robots `Disallow: /`). Judge canary: the GovExec MSPB article → one call, ~$0.03, a tip citing the 2026-08-02 OPM final rule that rendered MSPB appeal procedures inoperative. Dry-run precheck since 08-24: 12 articles (katz 7, wagner 5, rosenberg 0), cap 24, ~$0.54. **Gate result: pending — the owner scores `.tipwire-dryrun/decisions-template.json`; `pnpm tips:score` prints precision and the cron-slot recommendation.**

**Lessons learned**: (1) Probe every outlet before believing "RSS solves it" — one of three had no feed, one was walled, and the one with a feed lacked bylines. (2) A robots `Disallow` is the publisher's answer; an existing unaudited use is a discrepancy to fix, not a precedent to extend. (3) Per-category document rows and listing pages that mix index links with article links both need lineage/identity keyed on the logical thing (granule, dated article), never on row or URL shape alone. (4) When re-sorting reranked output, the input order is the signal — verify the base score is non-degenerate before boosting.
