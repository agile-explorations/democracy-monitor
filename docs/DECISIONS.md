## Sprint R-TIPWIRE-4: beat tips for feedless reporters, and "did the outlet already run this?" (#872–#878, milestone 139) — 🟡 built 2026-09-08; gate #878 pending on prod

**Origin**: the owner asked whether the eight roster reporters with no sanctioned byline source (Parloff, Schwellenbach, Natanson, Diamond, Hesson, Aleaziz, Ainsley, Cooke) could get beat tips. The beat pass never needed a feed — its documents are our own Pass 2 verdicts — only `activeReporters()` (active && feed) kept them out. What a feed did supply was the "already wrote it" dedupe, and the owner reframed that: GDELT cannot list articles by byline (no author field), but "did the **outlet** already run this?" is the better question anyway — a colleague's story kills a tip as surely as the reporter's own. The coverage check already asked GDELT about every tip and threw the own-outlet hits away.

**Diagnostic (prod, read-only)**: concerning Pass 2 docs in the last 14 days: immigrationEnforcement 9, civilLiberties 6, fiscal 5, judicialIndependence 3, civilService 2, infoAvailability 2, executiveOversight 2, lawEnforcement 2, executiveActions 1. Five reporters share immigrationEnforcement, so per-reporter beat checks would have produced five near-identical candidates for one opinion. The first live beat block (candidates 14–16, week 2026-08-31) had every coverage line `not-checkable` from 10 s timeouts; GDELT answered the same query in 25 s from the laptop and 429'd a second call minutes later — server-side load, not an IP block — so v1.29.1 raised the abort to 45 s (#867 stays open until a scheduled poll reads `ok`).

**Owner decisions 2026-09-08**: all eight join through ONE owner-scored beat dry run (gate: precision ≥ 0.5 on ≥ 3, zero wrong_fact); one candidate per document with every eligible reporter listed and the owner choosing recipients; the own-outlet signal for every reporter, feed-bearing included; a tip whose check could not run still ships, flagged "search the outlet before sending".

**Built (S1–S6)**: `feedReporters()` (probe/discover/watches) vs `beatReporters()` (active, feed optional) + `--reporter a,b` so the gate reaches inactive entries (#872). Migration 0070: `tip_candidates.beat_category`, `reporter_ids` (snapshot; `reporter_id` = first listed, so the 0069 CHECK is untouched), one index — additive, pinned by test (#873). Coverage keeps every hit and records `hitsByDomain`; `coverage-line.ts` renders `Own outlet — X (domain): N hit(s)` per listed outlet plus `Others: N`, says `unknown … re-run pnpm tips:coverage --candidate N` for checks stored before the split, and `outlet check unavailable — search the outlet before sending` when GDELT was down; no extra GDELT calls (#874). **Beat checks are per category, not per reporter**: `beat-docs.ts` queues one item per category any beat reporter covers, with a per-category clock (legacy per-reporter rows stand in via their reporters — no data backfill) and a global cited-doc exclusion across kinds (#875). `pipeline-frame.ts` builds a multi-reporter frame (titles loaded per reporter; beat anchors never reactive); the prompt gains `REPORTERS ON THIS BEAT`, per-reporter headline blocks with `(no feed — recent headlines unknown)`, and the role sentence "absence of headlines is NOT evidence the story is unwritten"; `TIP_PROMPT_VERSION = tip-2026-09-08-beat-group`; forward and contradiction prompts are pinned byte-identical to a fixture frozen before the edit (#876). Digest blocks list every reporter with cadence + send state; `tips:sent --candidate N --reporter a[,b]` logs one row per reporter and the candidate stays `open` until every listed reporter has one (`--dismiss` closes the rest); a beat check is cadence-skipped only when every listed reporter is held; `scripts/tipwire-beat.ts` + `tipwire-shared.ts` split the 647-line CLI (#877).

**Design calls (technical)**: grouping by category IS the dedupe (each document has one category), so no second mechanism; steady state ≤ 9 beat judge calls per new Pass 2 week (one per category with a beat reporter) vs 3 before. Global exclusion means a document tipped forward to one reporter is never beat-proposed to another — flagged on #875, reversible by scoping to beat rows. The beat frame changed for the three feed reporters too, so the #878 gate covers all eleven.

**Post-sprint review (`/code-review high`, ten verifiers)** — every confirmed finding fixed before commit: the anchor article's own URL is now excluded from its tip's coverage hits (it was flipping forward tips to `likely-covered` once outlet-wide drops went away; `CoverageChecker(keys, excludeUrls)`); the legacy per-reporter clock fallback in `lastBeatWeek` was deleted (a roster edit could silently move it; the three pre-0070 rows re-check once minus their cited docs) and the date cast is UTC-pinned; held reporters are now dropped from a beat candidate's listing and reported as skipped (a stored candidate never lists someone the owner must not send to) and `recordSent` re-applies the cooldown at send time unless `--ignore-cadence`; `--dismiss` with `--reporter` is refused instead of silently dismissing everyone; `recordReply` validates against the listing and the unreplied set with distinct messages; the reminder no longer offers `--dismiss` on a sent candidate (cooldown lifts by itself after 3 weeks); `tips:coverage` also picks up checks stored before the split and never overwrites a measured label with a fresh not-checkable; `tips:score` attributes a category check to every listed reporter; the digest cross-references a reporter listed on several open candidates (`· also on #N`); article rows no longer name the 0070 columns, so a cron on a pre-migration schema still persists them; outlets shared by several listed reporters render once; feedless reporters skip the stored-title lookup; `categoryLabel()` replaces three `categoryLabels([k])[0]` spellings; `listBeatWeeks` uses `getMonday`/`addDays`. Accepted as designed and documented: the cited-doc exclusion is global across kinds AND dismissed rows (one candidate per document, ever; reversible by scoping to beat rows); a multi-category reporter can be listed on two checks in one week (the cross-reference is the guard).

**Lessons**: (1) When only one prompt mode should change, freeze the others into a fixture BEFORE touching prompt code; the equality test is the re-gate exemption. (2) "Drop the reporter's own outlet" hid exactly the signal the owner wanted — a hit is a hit; render the split, do not filter it. (3) `gh issue create --milestone` takes the milestone TITLE, not its number; seven issues silently failed to attach on the first try. (4) A 10 s abort against a service that answers in 25 s reads as an outage; measure latency before suspecting a block.

**Next (S7, #878)**: tag release (migration runs in buildCommand, additive) → owner runs `pnpm tips:dryrun --beat --weeks 3 --out DIR --reporter katz,wagner,rosenberg,parloff,schwellenbach,natanson,diamond,hesson,aleaziz,ainsley,cooke --max-calls 30 --confirm` on prod (precheck on dev: see the issue; ≤ 27 checks, ≈ $0.70) → `tips:score` → on PASS flip `active: true` on the eight + release.

## Sprint R-TIPWIRE-2: from retrospective annotation to standing watches — the forward window, the contradiction pass, and the gate that passed (#862–#864, milestone 137) — ✅ built 2026-09-07, gate PASS (3/3 would_send, 0 wrong_fact)

**Origin**: the R-TIPWIRE dry run proposed ten tips on twelve articles and the owner rejected two of the three scored as _already known to the reporter_ — one was literally in the article body. The judge had been asked "what in the record is relevant to this piece?", which rewards restating context. The owner's reframing: an article is a thread the reporter is on; the useful question is _what appeared in the record since the piece was filed_. Approved as "pivot now".

**Planned vs built**: all three issues landed on develop in one commit (7b1b8c0). (1) **Window and watches** (#862): every dated article becomes a 21-day standing watch (`tip_articles.watch_until`, `last_checked_at`); `RetrievalScope` is `forward` (from max(article date, last check) to tomorrow, already-cited documents excluded) or `contradiction` (84 days ending at the article date); an empty forward window is reported as `skippedNoDocs` and costs no judge call; the daily poll runs a contradiction pass over brand-new reactive articles, then a forward pass over every open watch. (2) **Prompt** (#863): `tip-2026-09-08-forward` — the forward role asks what moved on the thread and frames the tip as "since your piece on X, this appeared"; the contradiction role sees the article body (fetched at judge time, bounded to 3,000 chars, never stored) and must cite a predating document that _contradicts_ it — additions are not contradictions; confidence rubric (high = verbatim passage, medium = content excerpt, low = inferred) and `search_keys` for the operator's own check. (3) **Forward dry run as the gate** (#864): same 12 articles since 2026-08-24, forward from each article date. Deviation from plan: none in scope; one in mechanics — the first run against the **dev** database made zero judge calls because the dev snapshot ends 2026-08-24, so the gate run read the **prod** corpus (owner-run; read-only; the dry run writes no tip rows).

**Gate result**: 12 judged, 12 calls (~$0.30), 3 proposed (75% no_tip), owner verdicts 3 would_send / 0 would_not / 0 wrong_fact → precision 100% on 3 decided, **PASS**. The three: the MSPB final rule dropping mandatory Douglas-factor review, published the same day as Wagner's Oyer/MSPB piece; DOJ's Massachusetts-primary monitor release with the cumulative 80-monitor figure, same day as Katz's Dhillon piece; the Federal Register text of the EEOC proposed rule the day after Wagner's vote story (owner: "confirms the flag raised by the article — useful until reporters tell me otherwise"). 25% of articles published before 10:00 ET → the single 21:30 UTC cron slot stands.

**Key decisions**: watches expire at 21 days (three weeks matches the cadence cooldown); cited documents are excluded from later checks of the same watch so a tip is proposed once; the contradiction pass is reactive-only (< 24 h) because a contradiction is only worth a same-day note; the article body is fetched for the contradiction judge and discarded — the no-news-in-`documents` boundary test still passes; a cap trip mid-forward-pass leaves `last_checked_at` untouched for unreached watches so the next run resumes where it stopped. Known gap, accepted at review: an article with no publish date gets no watch and no contradiction pass (it cannot be placed in a window); all twelve dry-run articles carried dates.

**Lessons learned**: (1) Ask the judge the reporter's question, not the archivist's — "what's relevant" produced ten tips of which most restated context; "what happened since" produced three, all accepted. (2) A dry run against a stale snapshot can pass every gate and mean nothing: check `max(published_at)` against the window before spending. (3) Extract the mode-dependent bits (window, structural anchor, body) into a scope object rather than branching inside the pipeline — the poll composes two passes from the same `runPipeline`.

## Sprint R-TIPWIRE: tip candidates for journalist follow-ups — an operator tool built to be killed cheaply (#853–#859 + #860, milestone 136) — 🟡 built 2026-09-07; retrospective gate superseded by R-TIPWIRE-2's forward gate (PASS)

**Origin**: first-round journalist outreach produced acknowledgments and no engagement. The pivot is findings-first follow-ups: a three-sentence tip naming one document, number, or discrepancy relevant to something a listed reporter published this week. The input the project deliberately lacks is what each reporter published; this side pipeline supplies it and drafts candidates. The owner sends manually; nothing auto-sends; no public surface; news never enters `documents`.

**Planned vs built**: all six slices landed on develop (roster + tables + dump exclusion + robots + PK note; acquisition; matching; judge; dry-run packet + score; poll/digest/sent + cron). Two plan deviations, both owner-decided during implementation: (1) **no Google News RSS** — its robots.txt disallows `/rss/search`, and "it's a syndication feed" is exactly the rationalization the probe-gated rule exists to prevent; the pre-existing intent-data use of that endpoint is a discovered discrepancy, filed separately as #860 rather than inherited. Parloff/Lawfare therefore has `feed: null` (manual tips) and **Mica Rosenberg / ProPublica** joined v1 in his place — a better gate subject, since her articles arrive with ledes. (2) **Rosenberg via her ProPublica people page**, not the site-wide RSS: the feed shows only the latest 20 items site-wide, the people page lists 16 of her articles, and article pages carry `parsely-author` metas. NOTUS gained a sitemap intersection (author page ∩ monthly sitemap = dated real articles, newest first) after the first live run wasted its page budget on columnist index links that share the article URL shape.

**Key decisions**: tables over JSONL (a Render cron has no persistent disk); one CLI file with subcommands so the whole tool is one deletion; the category prior is rank-based (+0.15 ≈ 1.5 places in ten) because reranked docs carry no comparable score — the first version silently re-sorted by zeros and discarded the reranker's order; `assertAiCallBudget()` outside the per-article catch, `recordAiCall()` before every request, hard 30-call daily cap with exit 3; the same-story guard reads stored titles in the poll and batch titles in the dry run; the ship gate is precision ≥ 0.5 on ≥ 3 decided tips with zero `wrong_fact`, and fewer than 3 proposed tips is unmeasurable, not failed.

**Evidence**: probes 2026-09-07 (GovExec RSS + `sailthru.author`; NOTUS author page + JSON-LD, Crawl-delay 10; ProPublica people page + `parsely-author`; Lawfare/POGO Cloudflare-walled; news.google.com robots `Disallow: /`). Judge canary: the GovExec MSPB article → one call, ~$0.03, a tip citing the 2026-08-02 OPM final rule that rendered MSPB appeal procedures inoperative. Dry-run precheck since 08-24: 12 articles (katz 7, wagner 5, rosenberg 0), cap 24, ~$0.54. **Gate result: pending — the owner scores `.tipwire-dryrun/decisions-template.json`; `pnpm tips:score` prints precision and the cron-slot recommendation.**

**Lessons learned**: (1) Probe every outlet before believing "RSS solves it" — one of three had no feed, one was walled, and the one with a feed lacked bylines. (2) A robots `Disallow` is the publisher's answer; an existing unaudited use is a discrepancy to fix, not a precedent to extend. (3) Per-category document rows and listing pages that mix index links with article links both need lineage/identity keyed on the logical thing (granule, dated article), never on row or URL shape alone. (4) When re-sorting reranked output, the input order is the signal — verify the base score is non-degenerate before boosting.

## Sprint R-EO-FR-FILTER: the diagnostic that overturned its own premise (#846–#848, milestone 135, v1.24.0) — ✅ built 2026-09-03

**Planned vs built**: The owner green-lit #548's parked "light-touch FR term retargeting" for executiveOversight before congressional outreach. The diagnostic disproved the plan before code: every lexical instrument (query phrasing, exact phrases, title matches, mention position, mention density) was measured against the 20 current-term P2-confirmed FR docs and the ~580-doc noise corpus — the confirmed docs are lexically indistinguishable from boilerplate (1–2 buried mentions, no title signals; relevance was established by AI reading, not phrases). Presented A/B options; owner chose both. Built: #846 query hygiene (fr_ig_personnel had invalid FR query syntax — the API silently drops the parenthetical, making it a byte-identical duplicate of fr_inspector_general, verified by result-set comparison; "government accountability" dropped after buying 185 docs per confirmation); #847 the first **exclude-driven** relevance filter (mode flag in the #524 machinery: keep by default, drop only title-identified noise classes, allow-list as rescue; 59% noise kill at zero false drops on the protected holdout); #848 the rehearsed prod chain (2,000 docs dropped across all eras, **zero status flips**, 39/39 + NC 6/6 on the post-state).

**Key decisions**: exclude-driven over allowlist (an allowlist would have dropped most confirmed docs — their titles are generic); default-keep philosophy for borderline cases (the category errs toward inclusion, stated in methodology); no reroute arm (droppable docs are unconfirmed and mostly exist under sibling categories already).

**Lessons learned**: (1) Measure a parked recommendation before executing it — #548's rec was written without the lexical-separability measurement and could not have worked. (2) Two measurement traps found the hard way: stored FR content is abstract-only (~600 chars) for most notices, so SQL content matching under-detects phrase presence (full text lives behind raw_text_url); and grep silently fails on FR's binary-ish full text (python byte counting is the reliable check). (3) Validate external-API query syntax by comparing result SETS, not counts — the broken parenthetical was invisible until the malformed query's document_numbers matched plain-phrase's exactly. (4) An exclusion-mode filter makes the zero-false-drop gate structural: confirmed docs can only be lost if an exclude names them, which the holdout test pins forever.

## Sprint R-GRADED-EVIDENCE: the strongest claim now requires an action (#837, #841–#845, milestone 134, v1.23.0) — ✅ built 2026-09-02

**Planned vs built**: the #837 decision (owner: graded — CC requires ≥1 action-tier confirmation; discussions counted at reduced weight; visible action/discussion distinction on category pages; the choice explicit on the methodology page) built as five work items in one day on the R-INFOAVAIL machinery: #841 CREC subtype override (evidence_tier column, five positive title classes, 13,771 promoted, speeches never promoted — speakerless includes failed-extraction speeches, discovered by diagnostic); #842 graded synthesis; #843 tier badges + evidence-mix disclosure; #844 methodology copy; #845 rehearsed acceptance package.

**Key decision the calibration forced**: variant B over the naive design. Full-corpus simulation (7,029 weeks, strict per-event minimum-status check) showed weighting BOTH thresholds Stabled ~510 Elevated weeks and broke known-event detection at every weight — contradicting "discussions should be counted." Variant B keeps Elevated thresholds raw (discussion counts in full toward attention) and grades only the CC path (weight 0.5 + ≥1-action gate). Result: the flip surface is purely CC→Elevated — 395 weeks (T1 252 / Biden 28 / T2 115), zero collateral, 39/39 + NC 6/6 preserved, NC margins bit-identical. The real 14-category enrichment replicated the simulation exactly.

**Lessons learned**: (1) Calibrate against the corpus before trusting a threshold design — the "obvious" implementation violated the owner's stated intent measurably. (2) Simulation bugs announce themselves as impossible results (day-one EO week → Stable); chase the impossibility, found three: audit-sample NULL semantics (`= false` excludes legacy NULLs — use `IS NOT TRUE`), SQL three-valued logic (`NOT(x OR y)` with NULLs silently empties a filter — write both branches positively), equality-vs-range week joins (enrichment uses a Monday-window RANGE). (3) `while read` drops the last line of files without trailing newlines (bit the narrative fleet; two units recovered). (4) Optional summary fields + fallback semantics let a scoring change deploy with zero behavior change until re-enrichment — the whole legacy suite stayed green untouched.
